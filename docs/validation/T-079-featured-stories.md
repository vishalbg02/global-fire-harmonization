## 4. Queries

Run with DuckDB on `data/products/` (the script runs exactly these):

```sql
select entity_type, entity_id, entity_name, year, month, verdict, pct_of_normal, estimate, ci90_low, ci90_high,
       baseline_median, baseline_p25, baseline_p75, p_above, p_below, p_within, reason_codes, data_level, n_witnesses,
       disagreement_scale, raw_combined_cell_days
from read_parquet('data/products/entity_month.parquet') where entity_type = 'COUNTRY' and year = <year> and month = <month>

select h.verdict, count(*) as n
from read_parquet('data/products/cell_month_harmonized.parquet') h join read_parquet('data/products/cells.parquet') c using (cell_id)
where c.country_iso3 = 'AUS' and h.year = 2019 and h.month = 12 [and h.estimate >= 20 and h.estimate > 3 * h.baseline_p75]
group by h.verdict order by h.verdict
```

Rank: take the rows of the query for the type and month whose verdict is `ABOVE_NORMAL` or `BELOW_NORMAL`; order by the larger of `p_above` and `p_below` at the displayed precision (0.995 or more counts as equal, otherwise the whole percentage) descending, then `abs(ln(pct_of_normal / 100))` descending, then `entity_id`; the rank is the position among the rows with the entity's own verdict (the app's list; `pipeline/number_check.py` `anomaly_order`).
